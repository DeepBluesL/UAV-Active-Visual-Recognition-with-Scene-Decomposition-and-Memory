# UEVAVD 阶段 1/2 实验协议

本协议固定于 2026-10-22，目标是重建可审计的离散环境、跑通 MAP 基线，并与已有规则策略作同条件比较。参考用户指定的 [arXiv v1](https://arxiv.org/html/2411.04348v1)，不是后续版本。作者 GitHub 在本次检查时仍只有数据说明；未提供策略代码和权重。本文的“MAP”均指下述 **MAP-style 自行实现**，不表示数值或所有训练细节与作者实现完全一致。

## 论文明确给出的设置

| 项目 | 本次采用 |
|---|---|
| 分类器 | 固定 ImageNet ResNet18 微调分类器，复用 `output/demo/classifier.pt` |
| 决策图像编码器 | ImageNet ResNet50 |
| 场景划分 | 每类前 20 个训练，中间 5 个 simple test，最后 5 个 hard test |
| 动作类型 | 六个坐标轴方向和 STOP |
| 动作幅度 | 1、2、3、4 个单位，一个单位 10 m |
| 决策上限 | 5 |
| 折扣 gamma | 0.9 |
| 终止奖励 xi1 | 成功 +0.5，失败 -0.5 |
| 非终止惩罚 xi2 | -0.1 |
| 移动惩罚 C | 每单位 -0.02；STOP 不扣距离成本 |
| 优化器与学习率 | Adam，1e-4 |
| 全量训练预算 | 300,000 episodes，64 个并行环境可能完成至多额外 63 个 episode，实数写入日志 |

原文 Table I 的范围有明显不一致：例如第二类 hard 范围写成 56…80、最后一类训练含 120。这里按原文每类 30 场景、20/5/5、总计 100/25/25 的结构解析为互不重叠的清单，保存为 `splits.json`；不是盲目照抄有重叠的区间。

## 决策与奖励时序

在当前观察上选动作。STOP 不移动；其他动作先移动，再获取到达位置的观察。若选 STOP，或当前是第 5 次决策，回合结束，否则继续。

```
terminal success:  +0.5 - 0.02 * action_range
terminal failure:  -0.5 - 0.02 * action_range
nonterminal:       -0.1 - 0.02 * action_range
return:            sum(gamma**t * reward_t)
```

第五次决策仍可移动，随后强制结束。因此最多 5 次移动/6 个观察位置。STOP 重复返回当前位置，不产生新移动。原 demo 的“最多 5 个观察、4 次移动”与此不同，旧报告不能直接作为新协议下的结果。

`action_range` 用 10 m 的单位计量，米数单独记录。越界动作在动作选择前统一屏蔽；不进行截断移动、位置钳制或隐式 STOP。动作编号 0…23 是六方向×四幅度，24 是唯一 STOP。`z` 使用数据文件中的 AirSim NED 负数，上升是 z 减小。数据集不提供飞行通道的碰撞判定，这里不模拟物理碰撞或真实无人机。

## 识别成功的歧义与采用的解释

原文式 (2) 说 `reco` 表示识别正确，后文又以分类分数超过 `thre` 描述成功，没有明确说明是否只比较真实类别分数、是否另外要求 top-1 正确。引用的 MAP 2019 论文官方页面无法获取完整内容，不能把推测当作已核实事实。

本次默认 `top1_and_true_probability`：目标可见、top-1 类别正确、真实类别分数严格大于 0.2，三者同时满足才成功。也提供 `--success-mode true_probability` 的替代解释，便于后续敏感性实验。本次没有把两种口径混合选优。准确率始终按真实 top-1 正确率统计，不因奖励模式而改变。

五分类最大概率至少为 0.2，故不能以“最大概率 >0.2”直接判作成功或直接 STOP。真实类别只在环境奖励和事后评估中使用，从不输入 MAP 网络；这与用监督标签计算训练奖励不同于测试时给策略答案。

空框 `[0,0,0,0]` 对应不可见目标，分类器不执行，概率为全零、预测 Unknown。此时不成功。论文的跟踪输入在本次用给定 GT bbox 代替，尚不复现在线目标检测/跟踪。

## MAP 网络及未公开细节的实现选择

```
RGB full view -> frozen ResNet50 -> 2048 features -> LayerNorm -> Linear/ReLU ->512
bbox / 256 -> Linear/ReLU ->32
concatenate ->544 -> Linear/ReLU ->512
  -> state value V (1)
  -> direction advantage Ad (7, includes STOP)
  -> range advantage Ar (4)
```

移动 Q 值为 `V + (Ad[d]-mean(Ad)) + (Ar[r]-mean(Ar))`；STOP 为 `V + Ad[STOP]-mean(Ad)`，不带幅度项。联合计算全部 25 个动作并施加合法 mask，不分别取两个分支的 argmax 再拼成越界动作。

ResNet50 使用官方 ImageNet V1 权重，完整 256×256 RGB 直接缩放至 224×224。特征提取使用 CUDA float16 autocast，缓存 float16；训练投影层与 Q 网络用 float32。编码器冻结、层宽、LayerNorm、分支组合、STOP 的幅度处理、输入缩放均明确记录为本次实现选择；论文未公开这些全部细节。没有 SAM 和 GRU，符合本阶段先做无记忆 MAP 基线的范围。

训练使用 Double DQN 目标、均匀 replay 100,000 条、batch 256、64 并行环境，每个向量步一次梯度更新，2,048 条转移后开始学习。epsilon 在训练前 70% 的完成回合中从 1 线性减到 0.05，之后保持 0.05。每 500 次梯度更新复制 target 网络，Smooth L1 损失，梯度范数裁剪 10。这些均为缺失超参的显式选择。相比单环境逐步更新，该并行更新比例也属于实现差异。

Replay 只保存当前/下一观察索引、动作、奖励、终止标志，特征从只读缓存取出；终止转移不 bootstrap。探索动作包含 STOP；预测不可访问未来图像、未来分数、场景 ID 或真实类别。

## 训练与模型选择

1. CPU smoke：训练场景 1，约 2,000 episodes，只验证代码能学习，不用于模型选择或最终报告。
2. Development：从原文 100 个训练场景中，每类取第 19/20 个为验证（10 个），其余 90 个训练 30,000 episodes。只按这 10 个验证场景的回报保存 best。
3. Full：重新初始化相同结构，在全部 100 个训练场景上运行 300,000 episodes，使用最终 checkpoint 评估。不是按 hard test 结果选中间 checkpoint。

当前执行一个训练种子 42；论文的五训练种子统计不在阶段 1/2 的已完成声明中。所有随机状态、场景清单、训练参数、完成的 episode 数与更新数都记录在 `training.json`。GPU固定种子不保证跨驱动或硬件逐位相同。

## 公平比较

所有策略使用同一冻结分类器、同一观察缓存、每场景全部 605 个初始视点、相同合法动作 mask、5 次决策上限、距离成本、成功条件与回报公式。分别对训练、simple test、hard test 汇总。

| 策略 | 移动 | 原生停止 |
|---|---|---|
| stationary | 不移动 | 立即 STOP |
| sweep | 保留原 demo 先升高再横向扫描的规则 | 当前最大分类概率达到 0.90 |
| random | 随机选择合法且优先未访问过的移动动作 | 当前最大分类概率达到 0.90 |
| map | 学习的方向/幅度联合 Q 值 | 学习的 STOP 动作 |

扫描、随机保留自己的访问历史以避免重访；MAP 是单观察策略，无禁止重访约束。这是各策略本身的区别，不能把 random 描述成完全无记忆、在所有合法动作上均匀采样。两种启发式策略的 0.90 阈值沿用既有 demo，没有利用本次测试集调参。

额外在 hard test 做 `fixed_3_moves` 诊断：三种移动策略都忽略原生停止规则，恰好移动 3 次再 STOP，用于区分移动选择与停止规则的影响。它只控制移动次数，步长不同仍可能导致米数不同，不称为相同距离预算实验。

主要指标为真实 top-1 准确率、折扣回报、平均米数、平均决策次数；同时报告 STOP/强制结束比例、错转对/对转错、错误停止数和训练到 hard test 的回报差。置信区间以场景为 bootstrap 单位，避免把同场景 605 个相关视角当作 605 个独立样本；这些区间不代表训练种子的不确定性。

每个 episode 的起点、终点正确性、停止原因及指标写入 `evaluation.csv`；每一步的位置、动作、奖励、五类分数写入 `trajectories.jsonl.gz`。展示案例明确标记为事后选择，总体指标包括全部起点。

缓存同时校验 NPZ 内容 hash，以及所有场景共同的编码器权重、分类器权重、预处理和数据路径身份。checkpoint 保存该身份，评估必须一致。源图像指纹使用名称、大小和修改时间，标注使用 SHA256；运行缓存准备脚本会重新核对源数据。
